3. Données PGIIS Requises

3.1 Shapefiles nécessaires

⚠️ Important: Ces données doivent être obtenues auprès du PGIIS (Plan de Gestion Intégrée des Inondations Sénégal)
Couche Format Description Priorité
Zones inondables Shapefile (.shp) Polygones des zones susceptibles d'inondation (récurrence 10, 50, 100 ans) 🔴 Critique
Rivières & bassins Shapefile (.shp) Réseau hydrographique (Sénégal, Niger, Casamance, etc) 🔴 Critique
Lacs & retenues Shapefile (.shp) Points d'eau permanents et temporaires 🟡 Important
Zonage administratif Shapefile (.shp) Régions, districts, communes (pour filtrage d'alertes) 🟡 Important
Élévation du terrain DEM/GeoTIFF Modèle numérique de terrain (pour modélisation) 🟢 Utile
Données pluviométriques CSV/API Stations de mesure pluie (ANACIM) 🟢 Utile

3.2 Structure des shapefiles

Zones inondables (attributs suggérés):

SHAPEFILE: zones_inondables.shp ├── id (integer) - Identifiant unique ├── nom_zone (string) - Nom de la zone ├── region (string) - Région (Dakar, Thiès, Kaolack, etc) ├── district (string) - District/Département ├── commune (string) - Commune ├── type (string) - Nature (rivière, lac, mare, etc) ├── recurrence (integer) - Période retour (10, 50, 100 ans) ├── superficie (float) - Aire en km² ├── elevation_min (float) - Altitude minimum (m) ├── elevation_max (float) - Altitude maximum (m) ├── population (integer) - Habitants exposés (approx) └── geometry (polygon) - Limites de la zone

3.3 Contacts pour obtenir les données

  • PGIIS Sénégal: Plan de Gestion Intégrée des Inondations
  • ANACIM: Agence Nationale de l'Aviation Civile et la Météorologie (données pluie/climat)
  • ONAS: Office National de l'Assainissement du Sénégal (données réseau hydrographique)
  • IGN: Institut Géographique National (fonds de cartes, zonage administratif)
  • BRGM: Bureau de Recherches Géologiques et Minières (études géologiques/hydrogéologie)

4. Intégration des Shapefiles sur la Carte

4.1 Architecture proposée

Stack technique:
• Frontend: Vue 3 + Leaflet.js (déjà implémenté)
• Backend API: Flask (flood_api) + GDAL/Shapely pour parsing
• Format export: GeoJSON (shapefile → GeoJSON via GDAL)

4.2 Processus de conversion

Shapefile (.shp) → GDAL (ogr2ogr) → GeoJSON → Stockage JSON → Leaflet affiche

4.3 Implémentation Backend

Endpoint API proposé:

GET /api/zones-inondables Query params: - region (optionnel): Filtrer par région - recurrence (optionnel): 10, 50 ou 100 ans - format (optionnel): geojson (défaut) ou bounds Réponse: { "type": "FeatureCollection", "features": [ { "type": "Feature", "geometry": { "type": "Polygon", "coordinates": [...] }, "properties": { "id": 1, "nom_zone": "Bassin Sénégal", "region": "Saint-Louis", "recurrence": 10, "population": 50000 } } ] }

Code Flask proposé:

# flood_api/routes/zones.py from flask import Blueprint, request, jsonify import geopandas as gpd from pathlib import Path zones_bp = Blueprint('zones', __name__) @zones_bp.route('/zones-inondables', methods=['GET']) def get_zones_inondables(): region = request.args.get('region') recurrence = request.args.get('recurrence', type=int) # Charger shapefile gdf = gpd.read_file('data/pgis/zones_inondables/zones_inondables.shp') # Filtrer if region: gdf = gdf[gdf['region'].str.contains(region, case=False)] if recurrence: gdf = gdf[gdf['recurrence'] == recurrence] # Convertir en GeoJSON geojson = gdf.to_json() return jsonify(json.loads(geojson))

4.4 Affichage sur la carte (Frontend)

Modifications nécessaires dans PublicDashboard.vue:

  • Ajouter couche GeoJSON pour zones inondables
  • Implémenter filtrage par région/récurrence
  • Afficher popup avec attributs (population exposée, etc)
  • Colorer polygones par niveau de risque
  • Ajouter légende interactive
Exemple code Leaflet: 
// Charger zones inondables
fetch('/api/zones-inondables?recurrence=10')
  .then(r => r.json())
  .then(data => {
    L.geoJSON(data, {
      style: feature => ({
        color: feature.properties.recurrence === 10 ? 'red' : 'orange',
        weight: 2,
        opacity: 0.7,
        fillOpacity: 0.3
      }),
      onEachFeature: (feature, layer) => {
        layer.bindPopup(
          `${feature.properties.nom_zone}

           Population: ${feature.properties.population}`
        )
      }
    }).addTo(map)

5. Logique de Détection des Inondations (3h + Confirmation)

5.1 Concept: "Inondation confirmée" après 2 signalements

Problème: Un seul signalement ≠ certitude d'inondation
Solution: Attendre 3h + 2ème signalement = confirmation inondation
Bénéfice: Réduire faux positifs, augmenter confiance des autorités

5.2 Processus de confirmation

Alerte 1 créée → Marquer zone → Attendre 3h →

Si Alerte 2 reçue → Zone CONFIRMÉE → Notifier autorités

5.3 Structure Firestore

Collection: flood_zones

flood_zones/{zoneId}/ ├── zoneId: "dakar_medina_001" ├── nom: "Médina, Dakar" ├── region: "Dakar" ├── latitude: 14.7055 ├── longitude: -17.4732 ├── status: "pending" | "confirmed" ├── firstAlertTime: timestamp (première alerte) ├── confirmationTime: timestamp (2ème alerte reçue) ├── confirmationDeadline: timestamp (firstAlertTime + 3h) ├── alerts: [ │ { │ id: "alert_123", │ createdBy: "uid_citizen", │ time: timestamp, │ description: "Eau stagnante rue X" │ }, │ { │ id: "alert_124", │ createdBy: "uid_citizen_2", │ time: timestamp, │ description: "Route inondée" │ } │ ], ├── shapefile_zone_id: "zones_inondables_456" (lien PGIIS), └── notified_authorities: [ "mayor_email@...", "emergency_service@..." ]

5.4 Logique de détection (Cloud Function)

Pseudo-code:

function onNewAlert(alert): // 1. Récupérer zone inondable PGIIS contenant le point alerte zone_pgis = findZoneInondable(alert.latitude, alert.longitude) if zone_pgis NOT FOUND: return // Alerte hors zone à risque // 2. Chercher flood_zone existante (dernière 3h) flood_zone = findFloodZoneWithin3Hours(zone_pgis.id) if flood_zone NOT EXIST: // 3a. Première alerte = créer flood_zone flood_zone = create({ status: "pending", firstAlertTime: NOW, confirmationDeadline: NOW + 3h, alerts: [alert], pgis_zone_id: zone_pgis.id }) // Envoyer alerte rouge aux citoyens notify_citizens(zone_pgis.nom, "ALERTE INONDATION - À confirmer") else if NOW < flood_zone.confirmationDeadline: // 3b. Deuxième alerte avant 3h = CONFIRMER flood_zone.status = "confirmed" flood_zone.confirmationTime = NOW flood_zone.alerts.push(alert) update(flood_zone) // Notifier AUTORITÉS (maires, services d'urgence) notify_authorities(zone_pgis, flood_zone) // Envoyer SMS d'urgence sendEmergencySMS(zone_pgis) else: // 3c. Après deadline = nouvelle alerte flood_zone = create({...})

5.5 Seuil de détection géographique

Méthode: Buffer géographique

Une alerte déclenche une détection si elle se trouve:
• Zone inondable PGIIS: Intersection exacte
• Buffer: ±500m autour de la zone (pour signalements proches)

Implémentation:

function findZoneInondable(lat, lon): // Buffer: 500m = 0.0045° approximativement buffer = 0.0045 // Chercher zone PGIIS contenant le point zones = db.collection('pgis_zones').where( latitude > lat - buffer AND latitude < lat + buffer AND longitude > lon - buffer AND longitude < lon + buffer ).get() // Vérifier intersection exact for zone in zones: if pointInPolygon(lat, lon, zone.geometry): return zone return None
